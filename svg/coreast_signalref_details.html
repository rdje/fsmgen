Purpose

Represents a reference to a signal within expressions. This class acts as a wrapper around FSM::CoreAST::Signal objects and provides access to signal properties through delegation.

🚨 Current Issue

The name() method is failing because it assumes $self->{signal} exists and has a name() method, but it doesn't handle edge cases properly.

Current Implementation:

sub name($self) { $self->{signal}->name } # Convenience method for HDL generators

Error Message:

Can't locate object method "name" via package "FSM::CoreAST::SignalRef=HASH(0x160875fc8)" (perhaps you forgot to load "FSM::CoreAST::SignalRef=HASH(0x160875fc8)"?)

Root Cause:

  • The $self->{signal} might be undefined
  • The $self->{signal} object might not have a name() method
  • The SignalRef object might not be properly initialized

✅ Proposed Fix

Make the name() method more robust by properly handling edge cases while maintaining the delegation pattern:

sub name($self) { # Convenience method for HDL generators - delegate to signal's name return $self->{signal} && $self->{signal}->can('name') ? $self->{signal}->name : (defined $self->{signal} ? "unnamed_signal" : "null_signal"); }

Benefits:

  • ✅ Maintains encapsulation - doesn't expose internal structure
  • ✅ Handles undefined signal gracefully
  • ✅ Checks if the signal has a name() method before calling it
  • ✅ Provides meaningful fallback values for debugging
  • ✅ Follows object-oriented design principles

Usage Pattern

# Create a signal first my $signal = FSM::CoreAST::Signal->new(name => "my_signal", width => 8); # Create a reference to the signal my $signal_ref = FSM::CoreAST::SignalRef->new($signal); # Now you can call name() safely my $name = $signal_ref->name(); # Returns "my_signal" # With bit slice my $sliced_ref = FSM::CoreAST::SignalRef->new($signal, slice => [7, 0]); my $verilog = $sliced_ref->to_verilog(); # Returns "my_signal[7:0]"

Design Notes

  • This class follows the Decorator pattern - it wraps a Signal and adds expression-specific behavior
  • The delegation in name() is intentional to maintain the single source of truth for signal names
  • The class supports bit slicing for hardware description purposes
  • All HDL generation methods properly handle the optional slice parameter
