## Selected `.739` Contract

`.739` must add the matching profile-alias source:

```text
ppif/ahb_lite_subordinate_byte_lane.ahb
```

The alias must mirror the shipped generic source:

```text
ppif/ahb_lite_subordinate_byte_lane.ppif
```

It keeps explicit `(profile ahb)`, the same
`(ahb-subordinate ahb_lite_subordinate_byte_lane ...)` object, the same
source anchor, the same control, bus, storage, transfer, supported-size,
lane-order, narrow read/write, and unaligned/crossing policy clauses, and the
same generated review chain:

```text
.ahb / IAL2
  -> generated ahb_lite_subordinate_byte_lane.isf
  -> generated ahb_lite_subordinate_byte_lane.fsm
  -> HDL module ahb_lite_subordinate_byte_lane
```

The selected alias support-accounting identity is:

```text
entry_id: intent.ahb_profile_alias_subordinate_byte_lane
source_kind: ial2_profile_alias
coverage: ial2_ahb_profile_alias_subordinate_byte_lane_pipeline_cli

```

The alias report must remove only `ahb_subordinate_profile_alias_deferred`.
The generic byte-lane `.ppif` report must keep that residue. Both the generic
source and the alias must keep the remaining AHB residue for aggregate
byte-lane propagation, optional signals, burst `SEQ`, broader interconnect
and decode, direct backend behavior, verification-output generation,
backend-language variants, and VHDL.
