FSMGen Book

Transactions

A transaction is a behavioral sequence lowered into scheduled .fsm states and associated data-path logic. Declarations alone do not create execution.

It is useful to think of an ISF transaction as a hardware task: it consumes cycles, can declare local ports as formal arguments, and activation sites can pass actual signals through explicit bindings.

The hardware caveat is that the transaction is not a stack-allocated software/SV-task call.

It lowers to static scheduled .fsm states, handoff signals, mux selections, and generated top wiring.

Current direct-controller limitation: direct sibling transactions can emit disconnected state loops inside the same encoded FSM. Independent triggers then execute only the first declared loop. Plain local calls also have retained reachability failures. Source admission and schedule reports do not qualify those runtime combinations; repair is owned by .32.1.3.3.1. Generated-child activation has separately qualified controllers, as described in Composition.

The selected repair gives each retained transaction its own logical controller while keeping actor storage shared under its existing owner. It preserves source state identities and binding timing and must reject unproved competing writes. Decision 0109 defines that implementation contract; it does not mark the current reachability failures repaired. Production runtime and public-report qualification remain required before the warning above can be removed.

The shared-writer prerequisite is still open. Strict admission currently accepts siblings that write different values to the same actor register or output; transaction/transaction priority does not create a grant. The planned check must compare physical targets: two set-field operations on disjoint masks still perform whole-register read-modify-write, a bank store selects scalar entries, and two calls to a named drive can contend on its shared payload helper. Private formals remain separate from these shared targets. The retained direct writer baseline records these cases without claiming concurrent execution or silently selecting a winner.

A detached prerequisite can now compare resolved packed targets. For a record with a two-bit mode followed by a one-bit flag, frame.mode occupies bits [2:1] and frame.flag occupies bit [0]: each overlaps frame, but the two leaves do not overlap each other. Identical names in different modules remain separate. This target calculation is tested in isolation; it does not yet change writer admission or controller execution.

The detached declaration collector now matches the emitted +size entries for ports, actor storage, local/helper registers and assembly operands. It retains aggregate layouts and private formal widths. A sampled alias can have a known width in lowering without an explicit size declaration; such widths remain listed separately from explicit declarations. Collection also covers actual generated storage/completion handoff modules. It does not assert complete writer ownership or enable concurrent execution.

An implicit assignment such as (set copy captured) now has a detached whole-root overlap contract: any other write to copy overlaps, regardless of the width later inferred by the .fsm parser. This avoids guessing a width at scheduling time. Different roots and modules remain separate. Partial paths still need a resolved declaration layout; a missing layout cannot establish disjointness. Native and emitted-carrier semantic reports qualify this boundary; writer admission and controller execution remain unchanged.

The lowerer now records private transaction/domain membership, initial states and typed state references as a checked shadow model. It adds no public ports or controller storage and does not change emitted execution. This prepares scoped binding and writer checks; it does not yet make sibling transactions concurrent or repair local calls.

Private source-owner records now also identify the transaction that created a latency or monitor DT, the rule that created a rule DT, and the definition behind a named drive. State ownership continues to use the explicit transaction field. These identities survive source ordering and module/domain realization without parsing generated names. A transaction-owned monitor remains a DT with its own guards; its source identity alone does not prove state-based mutual exclusion. Shared drives retain all callers. Public reports and emitted carriers keep their existing contract while complete activation evidence is qualified.

A detached predicate collector now separates the conditions actually emitted for explicit assignments. For (when (& req allow) (sample data as captured)), the sample carries the compound predicate while the entry’s can_accept bookkeeping remains unconditional within that state. The entry condition stays separate from later transaction-body writes. DT writers retain their header condition and assignment condition separately; (when 0) remains a false header. Rule port guards retain their nested group placement, while latency comparisons and monitor expressions retain assignment suffixes.

Actual repeat-counter decrements have no emitted assignment guard. The collector refuses invented guarded-decrement forms instead of using a dropped condition as exclusion evidence. It validates raw/structured predicate consistency and returns detached records. These helpers remain detached from production admission. A resource-grant collector now cross-checks authored resource users against module grants and explicitly owned rule-DT grant records. It catches missing records even when both lowered copies omit them, preserves resource members and priority/round-robin policy, and joins through source identity after a DT rename. Priority higher entries describe fixed higher users; round-robin entries name potential blocking peers. Neither list alone proves exclusion. The lowerer now retains original requests and ordered guard transformations, including unchanged highest-priority grants and the actual round-robin pointer/update association. A detached validator now checks these requests against authored rules and joins every ordered transformation to the actual final header. It independently rederives resource priority and circular round-robin permissions and verifies actual pointer storage and updates. Target-local assignment suppressors, invocation joins and complete generated writer evidence remain separate work. The focused carrier and malformed-evidence checks run without HDL simulation:

scripts/run_with_ram_guard.sh prove -Iperl -It/lib t/1973-isf-writer-activation-predicates.t t/1975-isf-writer-resource-grants.t t/1976-isf-resource-activation-evidence.t t/1977-isf-writer-resource-activation.t

Scope repair now has separately tested expression, clause and binding resolution. It keeps caller values distinct from callee formal ports, retains generated-child public ports, and preserves state names, point labels and aggregate members. Normal compilation now gives each direct formal a private physical identity, separate from actor pins, actor storage and sibling formals. It applies the qualified resolver and checks actual declarations against prepared module scopes before emission. Generated-child ports retain their published names. This scope repair does not repair sibling-controller or local-call reachability.

Reservation preparation now retains the actual products of transaction lowering, including state assignments, counters, monitor logic and call records. This matters because a generated drive payload can have the same proposed name as a private formal: drive isf_port_main with parameter payload produces isf_port_main_payload, also the initial candidate for formal main.payload. The detached planner avoids that collision when supplied the product inventory, including case-only variants. Preparation also retains actual rule payloads, generated spawn/do/trigger handoffs and shared-drive products. For example, rule isf_port triggering main with input payload produces the same isf_port_main_payload candidate even when no transaction body uses that name. Detached rewrites now retain the formal’s source identity separately, so the rule payload helper keeps its authored name while the destination uses the private physical formal. Preparation also runs the actual local-call and external activation wiring routines on detached products. Cross-domain calls add ready ports and request states after transaction lowering; those names now participate in the inventory when preparing an actual projected domain. A generated ready port can otherwise collide with a proposed private formal just like a rule payload. Preparation also retains the actual active signals generated for (at NAME) checks and the actor output defaults added to entry states. Named points and activation labels keep their source identities after formal rewriting. Potential round-robin pointer names, widths and roles also come from the same declaration producer used by normal arbitration. This collection does not prove that the resource users, members or grants are valid; actual lowering still checks those contracts and rejects physical collisions. Preparation now also retains independently built generated-child modules, including their start history, storage read/write interfaces, named completion outputs and point-active signals. Tests compare complete child modules before and after parent formal rewriting, including reused definitions and projected clock domains; child public ports keep their own module scope. Parent preparation also retains the real completion memory used by generated-child joins: each used instance has an explicit record for its start/done handoffs, seen register and ready view. For example, (spawn worker as first) followed by (await_all done) retains first as the owner even if an authored name forces its completion helper to receive a suffix. Renaming a colliding formal may free the helper’s base name; its instance identity remains the same. Detached join products include the rewritten completion views in dynamic-wait guards, and retain raw done metadata. Declaration-name inputs remain separate from unallocated formal widths. Preparation also retains independently built reusable-library and resolved ATL children, their explicit bindings and origin, and the selected ATL child-interface records. The same producer performs module-conflict checks and supported composition selection in normal compilation. For example, a FIFO use retains its bound parameters and child bank operations, while a resolved ATL data route retains the actual child endpoint ports. These modules keep their own scope through parent formal rewriting. Production-stage checks now qualify the resource/priority boundary: arbitration adds the retained round-robin pointer declarations; priority guards reuse existing signals and state identities. Finalization checks provenance and conflicts without adding declarations. This does not grant resource validity to unallocated source products. Parent storage-write planning now retains actual potential data/enable ports, their storage widths and types, owner-side write DTs and explicit instance/storage links. For example, a worker writing actor storage value_reg keeps that target identity even if an authored name forces its parent data handoff to use a suffix. Normal compilation applies the same plan only after checking writer ownership; a collected plan does not admit competing parent or child writers. Existing scalar-writer checks preserve native, API and MCP report agreement. Storage-read planning also retains the actual shared owner output, type alias, combinational read DT and explicit consumer links. For example, separate worker instances reading value_reg share a live view identified by actor and storage; its generated name remains distinct from an authored rule with the same desired helper name. Reader allocation follows completion and write-handoff allocation, so those declarations are reserved too. The retained plan is detached from child and write products and preserves scalar, packed aggregate and selected bank reads through formal projection. Named-completion plans now retain per-instance parent inputs, optional local delayed-pulse storage and the output OR view after storage handoffs. For example, a child and parent completing notice keep their separate pulse sources while sharing the public output identity. The executable connection checks for non-completion writers before installing the plan and redirecting local completion assignments. A potential source plan does not admit those conflicting writers or merge raw formal storage contracts. Independent named-completion runtime and public report checks preserve the existing pulse timing, reset and repeated-activation behavior through this planning boundary. Library readback has been checked to preserve declaration names while adapting only the importing FSM’s interface direction and ownership role. Preparation now also constructs each actual domain source and retains its independent products. For example, an activation crossing introduces worker_start_ready in the caller and worker_idle_ext in the callee; a monolithic actor inventory alone misses those declarations. Domain products keep the logical domain identity, local transaction order and injected crossing contracts, without merging raw formal widths into an executable parent. Outer emission preserves the complete domain and child IR: module/file names, flat child instances, wiring labels and CDC interfaces belong to separate scopes. Detached formal projection preserves those outer identities and public ports. Combined domain checks now cover same-spelled private formals with different widths, actor-storage shadows, declaration-order changes, domain-local arbitration, generated reads/writes, named completion and control-only activation crossings. The prepared products plus allocated formal identities cover the actual domain declarations in these cases; competing storage writers remain rejected. A checked preparation collector now requires every product category, even an empty one, and checks live transaction, generated-child and domain membership. For example, removing the caller domain products is rejected rather than silently producing a smaller reservation set. Parent and child modules retain separate typed scope identities; the allocation union remains conservative. A separate final-module guard now compares actual parent/domain/child declarations with those prepared scopes and the canonical private allocation. Removing a real dynamic-wait helper from the inventory fails this check, as does adding an unreserved implicit assignment target. Private formals must also retain their planned width and ownership and cannot alias a fixed port or block. Normal compilation runs these checks before emitting the parent or any domain artifacts. Preparation also keeps the canonical authored binding report records: for example, caller payload and callee addr retain those source names in this snapshot even when executable endpoints receive private physical names. The snapshot preserves expression text, widths, timing and domain ownership. Public reports use these original records for binding provenance. Wait counts, loop conditions, temporal operands and bank-access expressions likewise retain authored names in a detached report view; executable operands remain physical. Inferred-storage entries identify the actual private storage and its width.

Source preparation can retain a monitor-name collision with an unallocated direct formal as pending physical work. The collision stays recorded with both identities; these preparation products are not executable modules. Fixed actor names, explicit locals, generated public ports and already renamed declarations keep their collision checks. Normal compilation allocates direct formal identities first and then requires the resulting modules to pass strict checks.

Today the task-like port model is shipped for (ports ...) bindings on do, spawn, and rule trigger activation sites.

Transaction port widths may be positive literals, actor-local scalar parameter defaults, declared actor constants, or qualified imported package scalar constants that resolve to positive integers. Generated child and direct/non-generated transactions may also use same-transaction scalar parameter defaults as port widths when they resolve to positive integers. Omitted widths are one-bit.

A direct transaction’s own parameters are compile-time inputs for the supported count, width and timing positions; they are not emitted as parent HDL parameters. These positions have different lookup rules from runtime expressions. For example, if a direct transaction has both (params (count 2)) and an input formal named count, (wait count) uses the parameter default, while (set observed count) reads the formal. Inside a dynamic wait expression such as (wait (+ count 4'd1)), count is also a runtime operand. Generated children emit their parameters in their own module. Actor parameters/constants and resolved enum/package symbols retain their existing expression lookup rules.

Input bindings may pass scalar actor-side signals, numeric/exact-width literals, or non-empty list expressions; output bindings still name scalar writable actor-side targets.

Binding validation resolves an explicit caller transaction port before a same-named actor pin or storage variable, using the caller port’s width. A callee port never supplies a missing caller variable. Rule bindings remain in actor scope: actor inputs are read-only and actor output readback is rejected. A direct formal may share an actor pin or storage name even when the widths differ. Writes address its private storage; the actor declaration keeps its own width and ownership. Explicit (local ...) ownership and the controller limitations described above remain separate work.

For example, this private four-bit payload neither drives nor reads the eight-bit actor input of the same name. The dynamic wait reads the private value:

(actor formal_shadow (clock clk) (reset (rst_n async active_low))
 (interface (input start) (input payload (width 8)) (input data (width 4))
  (output observed (width 4)) (output done))
 (transaction main (ports (input payload (width 4))) (on start)
  (set payload data) (wait payload) (set observed payload) (complete done)))

The schedule reports payload as the authored wait count source. Its inferred_storage table lists the allocated private name at width four. Read-only and unused direct formals are explicitly internal too: an unbound formal does not become a public input through usage inference. Retaining its declaration does not invent an initial value or a driver.

Generated child formals keep their own width, direction and type when they share an actor pin name. Explicit input bindings select the child payload; automatic same-name wiring does not add a second driver. The actor pin remains separate. See Composition for a complete example.

A callee formal name in (bind ...) is an identity, including when it shares an actor record input name. The caller actual still follows the admitted scalar binding contract. See the record-input binding example for the separate actor and child declarations.

Local rule triggers bind transaction inputs only. Generated/parameterized rule triggers also support scalar output bindings through completion-qualified handoffs. do and the shipped spawn path retain their documented output timing. Generated trigger inputs retain the per-rule captured payload beyond the start pulse, so delayed child reads see that snapshot rather than a gated zero.

Spawned child transactions and generated blocking do activations support per-instance parameter overrides through (params ...).

Those parameter overrides are compile-time specialization of a static child instance, not runtime payload actuals.

Parameterized rule triggers now use the same specialization model: they elaborate generated child activation instances instead of writing mutable parameter signals into a shared transaction body.

Direct (on ...) entry activation is explicitly not a parameter-override site because it is the transaction’s own guard, not a caller-owned generated instance.

Parameter overrides and port bindings must stay separate in authored intent.

Use (bind (input port expr) ...) for runtime data/control values that can change from cycle to cycle. Use (params (NAME value) ...) only for static specialization values on activation forms that explicitly support that surface: spawned children, blocking do generated child activations, and parameterized rule triggers. Use transaction ports and (sample ...) or activation-site (bind ...) entries for runtime-varying values.

(do read_word
  (params
    (WIDTH 16))
  (bind
    (input addr (+ base_addr offset))))

(spawn read_word as r0
  (params
    (WIDTH 16))
  (bind
    (input addr req_addr)))

(trigger read_word
  (params
    (WIDTH 16))
  (bind
    (input addr req_addr)))

The lowering contract for this surface is specialization, not assignment. A parameterized blocking do elaborates a generated child activation instance, applies the override in the generated composition top, starts that instance, and waits for its done handoff. Two activation sites that pass different parameter values to the same transaction must lower to distinct specialized transaction instances or cloned scheduled regions. They must not share one mutable parameter signal written at runtime.

Generated child parameters consumed by default-resolved static timing lowering have a stricter gate until full per-activation specialization exists. Overrides that target repeat counts, wait counts, latency bounds, or top-level await-local watchdog limits are accepted only when they resolve to the same integer value as the child transaction parameter default; mismatches fail closed before scheduled artifacts are emitted.

For rule triggers, a parameterized trigger also uses distinct generated hardware. The generated instance name is {rule}_{transaction}_trigger_{ordinal} so repeated lexical trigger sites do not collide. The rule still emits the existing one-cycle trigger source and payload source timing, then a generated trigger handoff DT drives the child instance start and input handoff ports. Generated-child rule-trigger output bindings copy the child output handoff into the scalar actor target under that trigger instance’s done-observer signal. Direct/local rule-trigger output bindings remain rejected because a shared local target has no rule-specific completion identity.

A blocking (do child) whose child runs in a different clock domain is not a direct activation: it must be owned by a declared activation crossing, which routes the start/done handshake through CDC synchronizers. See Activation Crossing. A cross-domain (do) without a covering crossing fails closed.

(do ...), (spawn ...), (await_all ...), and (await_any ...) are accepted as top-level transaction clauses, inside a repeat body, and directly inside a when body, a switch branch, a while body, and an until body (conditional / loop-conditional activation). A (do child) may be local (plain or with (bind ...) port bindings) or generated (a (do child (params ...)) parameter override); a (spawn child as inst) + (await_all ...)/(await_any ...) drain forms a conditional fan-out + join (the done-port accumulator is body-local, so the drain belongs in the same body as its spawns). See Where Child Activations Are Allowed for the full surface and the cross-domain staging.

How Transactions Become Hardware

(transaction name
  clause_1     → state_0  (entry)
  clause_2     → state_1  (1 cycle)
  clause_3     → state_2  (1 cycle or variable)
  ...)

Each clause is 1 cycle unless noted. The scheduler links states in order, adding transitions between them. There is no optimization, no merging — what you write is what you get.

(on port ...) — Entry/Idle State

(on ...) is the standard activation form. The guard must be a scalar port name. (when ...) can also be used as activation with identical semantics — useful for expression conditions: (when (> counter 5) ...).

The only supported inline body clauses inside (on ...) are (sample port as name) forms. Other body forms are rejected instead of being silently ignored.

(params ...) is not a legal (on ...) body clause. A direct entry guard has no per-call instance to specialize; the lowerer reports that direct (on ...) activation is an entry guard, not a generated activation-site parameter override. Transaction-local params on that transaction remain definition defaults. If an author needs a statically specialized child instance, use a generated activation form (spawn, parameterized blocking do, or parameterized rule trigger) and pass runtime data through ports or bindings. The optional (on SIGNAL as NAME) activation label only names the entry state for checks; it still is not a generated activation site.

Timing: 0 active cycles (waits). Fires in 1 cycle when condition is met.

Cycle-by-cycle:

  • Cycle 0..N: can_accept=1, wait for port=1
  • Cycle N: port && can_accept → samples captured, transition to state_1

What happens:

  1. The implicit can_accept signal is asserted (combinational, 1 in idle only)
  2. Watchdog counter loaded with (watchdog_N - 1)
  3. When port is true AND can_accept is true: samples fire (D-input capture)
  4. Transition to first body state

Generated .fsm:

(apb_transfer_idle_0
  (= (can_accept 1))              ;; implicit ready
  (<= (apb_transfer_wd 65534))    ;; watchdog: load max-1
  (<start                         ;; condition guard
    (<= (addr req_addr))          ;; sample: (sample req_addr as addr)
    (<= (is_write req_write))     ;; sample: (sample req_write as is_write)
    (-> apb_transfer_drive_1)))

When the entry activation is written as (when EXPR ...), the generated sample enables and entry transition use the rendered .fsm expression guard, not an implementation-internal representation:

(<= (hold din) <(& go (! busy)))
(-> main_done_1 <(& go (! busy)))

Literal entry guards also retain their meaning. With (when 0 (sample data as captured)), the sample bypass stays disabled and the transaction does not advance into its following body. Changing the guard to 1 allows both. The sample uses register-input (<=) semantics: when enabled, its visible value is the input mux value, including while reset holds the controller at entry. Reset still clears its underlying register. Entry guards control these samples and transitions; they do not guard every bookkeeping assignment, such as can_accept.

An entry when accepts inline samples. Other inline actions now fail with when activation body supports only '(sample port as name)' clauses. Place those actions after the entry guard:

(actor when_activation_samples
  (clock clk) (reset (rst_n sync active_low))
  (interface (input request) (input allow) (input datain (width 3))
             (output seen (width 3)) (output done))
  (transaction main
    (when (& request allow) (sample datain as captured))
    (set seen captured)
    (complete done)))

For a conditional action after accepting request, use a separate branch:

(actor when_branch_actions
  (clock clk) (reset (rst_n sync active_low))
  (interface (input request) (input allow) (input datain (width 3))
             (output seen (width 3)) (output done))
  (transaction main
    (on request)
    (when allow (set seen datain))
    (complete done)))

Declarations and (wait 0) add no preceding state. A when after them still selects entry activation. An initialized local or a positive wait creates a state, so a following when has the normal branch behavior. The entry-body evidence preserves actual source, public refusal and unchanged sample/branch controls.

(drive name args...) — One State per Call

Timing: exactly 1 cycle. The _start assertion fires in the current cycle.

The port value changes in the NEXT cycle (flopped).

Cycle-by-cycle (for (drive scl 1)):

  • Cycle N: scl_start=1, scl_val=1 asserted. Non-state DT (-scl) is enabled. The DT’s (<- (scl> scl_val)) schedules output scl to become 1.
  • Cycle N+1: scl output port = 1. Next state executes.

What happens:

  1. _start signal for the drive is asserted (=1)
  2. Parameter signals are wired to actual values
  3. The non-state DT (-drive_name ...) is enabled, doing (<- (port> param_val))
  4. Due to <- (flopped), the port output changes NEXT cycle
  5. State transitions to next

Generated .fsm — Drive DT (once per definition):

(-scl
  (<- (scl> scl_val) <scl_start))

Generated .fsm — Call state (once per call):

(i2c_transfer_drive_3
  (= (scl_start 1))               ;; enable the DT
  (= (scl_val 1))                 ;; wire actual to parameter
  (-> i2c_transfer_drive_4))      ;; next state

Consecutive calls:

(drive scl 1)    ;; cycle N:   state_3
(drive sda 0)    ;; cycle N+1: state_4  (separate state, no merging)
(drive scl 0)    ;; cycle N+2: state_5

(sample port as name) — No State, Piggybacks

Timing: 0 extra cycles. Fires on the transition of the enclosing clause.

The sample form is exact: (sample port as name). Both port and name must be scalar names. Missing as, nested names, and extra operands are rejected before scheduled .fsm emission.

What happens:

  • Creates a variable. The scheduler infers register if used across phases.
  • Inside (on ...): (<= (name port)) fires when guard triggers.
  • Before (drive ...) or (await ...): piggybacked onto that state.

No implicit signals. The variable name is tracked internally.

When a sample is followed by a data operation rather than a drive or await, the scheduler emits a sample state first so the data operation reads the captured value.

(await port) — Conditional Stall

(await PREADY)                        ;; default watchdog from actor
(await PREADY (watchdog 100))         ;; per-await override
(await PREADY (watchdog WD_LIMIT))    ;; actor constant or actor parameter override
(await PREADY (watchdog TX_LIMIT))    ;; same-transaction parameter override

Timing: 1 to watchdog_limit cycles. Self-looping.

The actor-level (watchdog N) and await-local (watchdog N) limit may use a positive decimal literal, a declared actor constant, or an actor-local scalar parameter default that resolves to a positive integer. Await-local watchdogs on top-level transaction awaits may also use same-transaction scalar parameter defaults that resolve to positive integers. Actor-level constants and actor parameters resolve in the parser-visible watchdog scalar and still appear in actor_constants[] or actor_params[]; await-local constants, actor parameters, and top-level transaction parameters resolve before watchdog counter injection. Same-transaction watchdog parameters shadow actor-level static names and remain local lowering inputs. Generated child activation overrides for top-level await-local watchdog transaction parameters must preserve the child default value; mismatches fail closed until per-activation watchdog specialization is shipped. The rejected shape is a parent that activates a child whose (params (WD_LIMIT N)) default feeds an (await ack (watchdog WD_LIMIT)) clause, when the activation site passes a different value:

(transaction parent
  (on start)
  (spawn worker as w0
    (params
      (WD_LIMIT 2)))         ;; <-- override mismatches the default
  (complete done))
(transaction worker
  (params
    (WD_LIMIT 4))            ;; child default drives the watchdog init
  (await ack (watchdog WD_LIMIT))
  (complete done))

The validator emits Transaction 'parent': spawn instance 'w0' overrides watchdog-limit parameter 'WD_LIMIT' on child 'worker'; activation-site parameter override-specialized watchdog limits remain deferred. The deferred lane is per-activation watchdog specialization, which would respecialize the child’s watchdog counter per call site.

One transaction currently has one watchdog counter. If a transaction contains multiple awaits with distinct effective watchdog limits, FSMGen fails closed until per-await counter reset semantics are selected.

Cycle-by-cycle:

  • Cycle N: check port and the current watchdog Q value
  • If port=1: transition to next state
  • If port=0: self-loop, repeat
  • If wd=0: timeout → error state
  • If wd>0: schedule the watchdog decrement for the next value

What happens:

  1. The await DT computes port, timeout, and decrement enables in the same cycle
  2. Guard (<port ...) fires when port is true
  3. Watchdog check (?wd (=0 ...) (>0 ...)) reads the current watchdog Q value
  4. On timeout: request the delayed done pulse, set last_error=1, return to idle

Generated .fsm:

(apb_transfer_await_3
  (<PREADY
    (-> apb_transfer_drive_4))
  (?apb_transfer_wd
    (=0 (-> apb_transfer_timeout))
    (>0 (-- apb_transfer_wd))))

(apb_transfer_timeout
  (<1 (done> 1))
  (<- (last_error> 1))
  (-> apb_transfer_idle_0))

The ordering in the source is not procedural. The ?apb_transfer_wd selector tests the current counter value in that cycle; (-- apb_transfer_wd) selects the next D value for the counter only on the >0 branch. The guard also avoids describing a zero-to-all-ones next-value underflow for the watchdog. Timeout normally exits the await state, so that old side effect does not necessarily escape as a system-level failure, but the scheduled artifact should still not ask the counter to decrement at zero.

(wait N) — Unconditional Exact-Cycle Delay

A positive static wait with no following statement holds in its final state. It does not invent a completion pulse or return to entry. Terminal (point NAME) and transaction (phase NAME) marker states likewise hold. Their scheduled carriers express an otherwise empty state with an explicit self-loop, preserving the source state and its named-point identity. An explicit continuation still advances normally; (complete done) supplies completion and return to entry.

For example, this actor enters the delay after start, then remains there until reset. Holding or pulsing start again does not restart it:

(actor terminal_wait
  (clock clk) (reset (rst_n async active_low))
  (interface (input start))
  (transaction main (on start) (wait 3)))

(wait 3)
(wait shared.WAIT_TWO)

Timing: exactly N active transaction cycles for static counts, or exactly the sampled runtime scalar count for the shipped dynamic subset.

(wait N) is different from (await port): it does not check a signal, does not consume an await watchdog, and does not have an early-exit condition. It is also different from (repeat count body...): it has no body and does not iterate any authored actions.

Cycle-by-cycle:

  • wait 0: emit no wait state, consume no active transaction cycle, and advance directly to the following transaction clause.
  • wait 1: occupy one generated wait state for one active cycle, then advance on that state’s transition to the next transaction clause.
  • wait N: emit N generated wait states and advance through them unconditionally, one per cycle for static counts.
  • wait PACKAGE.CONSTANT: resolve the qualified imported package scalar constant as a static non-negative count, preserving the authored qualified token in transaction_waits[].
  • wait count_signal: in shipped runtime contexts, bypass on a runtime zero count; otherwise snapshot count_signal on the predecessor edge and consume exactly that many active wait cycles with a generated counter. Consecutive top-level runtime waits are allowed; a zero bypass from one wait immediately evaluates the next wait’s zero/positive split, and the final sampled-counter edge of an active wait does the same for the following wait. (while cond body...) / (until cond body...) — Transaction Loops

(while cond body...) is a pre-test loop. The scheduler emits an entry decision state that samples cond once before the first possible body iteration; false exits to the next transaction clause, so zero iterations are possible. After each body iteration, a generated back-edge decision samples the same condition again before looping or exiting.

(until cond body...) is a body-first loop. The body executes once, then a generated decision state samples cond; true exits and false loops back to the body. A pre-test “run while not done” loop should be authored as (while (! done) body...) rather than by overloading until.

The condition uses the same scalar or list-expression guard surface as (when ...). It is sampled only in generated decision states. It is not a continuous guard over a multi-cycle body; once a loop body starts, its states run according to their own scheduled control flow until they reach the loop check or an explicit terminal path.

The shipped while/until body surface is the same inline transaction subset used by when/switch: named drives, await, sample, complete, repeat, update, set, shift/assemble/extract data operations, actor-owned bank store/load, nested when, and waits. while/until bodies continue to reject do, spawn, await_all, await_any, stage, contract, and nested loops until their re-entry, child-lifetime, and report semantics are specified.

The shipped repeat-body spawn plus same-body await_all or single-pending same-body await_any subset applies to top-level repeat bodies and, in the narrower branch-contained forms documented above, to repeats directly inside a top-level when body or top-level switch branch.

(when condition body...) — Decision State

Timing: 1 cycle. If true, body cycles follow. If false, skip to next clause.

The form is exact: (when condition body...), with a scalar or list-form condition and at least one list-form body clause.

What happens:

  1. (?condition (=1 → body_start) (=0 → skip_target))
  2. Body states execute if true
  3. Skip target is the next top-level clause after the when block

Generated .fsm:

(test_tx_when_2
  (?mode
    (=1 (-> test_tx_drive_3))
    (=0 (-> test_tx_when_5))))

(switch signal (val body...)...) — Multi-Way Decision

Timing: 1 cycle. Then matching branch body cycles.

The form is exact: (switch signal (value body...)...), with a scalar signal and one or more list-form branches. Each branch must carry a scalar value and at least one list-form body clause.

What happens:

  1. (?signal (=val1 -> branch1) (=val2 -> branch2) ... (default -> skip))
  2. Each branch body is expanded inline as sequential states
  3. Default fallthrough to next clause when no explicit branch predicate matches

Generated .fsm:

(dispatch_switch_4
  (?opcode
    (=0 (-> dispatch_drive_1))
    (=1 (-> dispatch_drive_2))
    (default (-> skip))))

The generated .fsm default selector means the logical negation of the OR of all explicit sibling branch predicates. For the example above, the skip path is taken only when neither opcode == 0 nor opcode == 1 matched. Authored ISF can also provide its own fallback branch with (default body...) or (_ body...); when it does, the scheduler does not add an extra implicit fallthrough branch.

(set var expr) / (update var expr) / (shift_left ...) / (shift_right ...) — Data Ops

Timing: exactly 1 cycle each.

(set var expr) is the canonical explicit scalar setter. It is exact: var is a scalar target and expr is one scalar or list expression payload. In a transaction it lowers as one ordered flopped assignment state. (update var expr) remains supported as the older transaction-local spelling for the same behavior. Division and modulo inside the RHS reject literal-zero, actor-constant-zero, actor-parameter-zero, and same-transaction-parameter-zero divisor operands before scheduled .fsm emission. Dynamic scalar divisors and nonzero same-transaction parameter divisors lower unchanged; full runtime nonzero proof is still backlog.

Shift operations are also exact scalar forms: (shift_left reg bit [(width N|TX_PARAM|PARAM|CONST|PACKAGE.CONSTANT)]) and (shift_right reg bit [(width N|TX_PARAM|PARAM|CONST|PACKAGE.CONSTANT)]).

The optional width value can be a positive literal, same-transaction scalar parameter default on a generated child or direct/non-generated transaction, actor-local scalar parameter default, declared actor constant, or qualified imported package scalar constant that resolves to a positive integer. assemble and extract use the same source set in ordered (widths N|TX_PARAM|PARAM|CONST|PACKAGE.CONSTANT...) lists. Unrelated or cross-transaction parameters remain fail-closed for this data-width surface.

What happens:

  1. (<- (var expr)) — variable modified, takes effect next cycle (flopped)
  2. Expression passes through to .fsm directly

Generated .fsm:

(i2c_transfer_shift_6
  (<- (rdata> (| (<< rdata 1) sda_in)))
  (-> next_state))

(latency (min N) (max M)) — Verification

Timing: no extra states. Adds counter + comparators.

The latency clause accepts one or both (min N) and (max N) options. N must be a positive integer literal, a declared positive actor constant, an actor-local scalar parameter default, a same-transaction scalar parameter default, or a qualified imported package scalar constant that resolves to a positive integer. Each option may appear at most once, and min must be less than or equal to max when both are present. Accepted symbolic bounds resolve before counter emission; the generated .fsm guard and timeout checks contain the resolved integer. Same-transaction parameters shadow actor-level static names and remain local lowering inputs. A valid explicit max bound drives the generated counter width and max violation check; omitted bounds use scheduler defaults. Unknown or unqualified package constants, aggregate package constants, package member/item paths, cross-transaction parameters, runtime signals, arbitrary expressions, zero-valued constants, and zero-valued or non-scalar actor/transaction parameters fail closed. Generated child activation overrides for latency-bound transaction parameters must preserve the child default value; mismatches fail closed until per-activation latency counter specialization is shipped. The rejected shape is a rule-trigger activation whose child default (params (LAT N)) feeds a (latency (min LAT) (max LAT)) clause, when the activation site passes a different value:

(transaction worker
  (params
    (LAT 4))                 ;; child default drives the latency window
  (latency (min LAT) (max LAT))
  (complete done))
(rule launch fire
  (trigger worker
    (params
      (LAT 2))))             ;; <-- override mismatches the default

The validator emits Rule 'launch': trigger instance 'launch_worker_trigger_0' overrides latency-bound parameter 'LAT' on child 'worker'; activation-site parameter override-specialized latency bounds remain deferred. The deferred lane is per-activation latency counter specialization.

What happens:

  1. Entry state: (<- (cc 0)) — reset counter
  2. Every active state: (= (inc 1)) — assert increment
  3. Non-state DT: (<- (cc (+ cc 1)) <inc) — increment
  4. Done state: (?cc (<N (lerr=1))) — min violation check
  5. Max violation: watchdog timeout

Implicit signals: {tx}_cc, {tx}_inc, {tx}_lerr + non-state DT (-cc_inc).

Local Variables

A transaction can keep named local state with (local NAME (width N) [(default V)]) (a declared internal register, optionally initialized each run) and name intermediate values with (let NAME EXPR) (pure substitution). These are documented in full, with examples, in their own chapter: Local Variables.

Reusable Procedures

A (proc NAME (params ...) body...) defines a reusable, parameterized block of clauses, called with (call NAME actuals...). A call can inline the body at the call site (default) or, with a trailing as INST, call the procedure as its own one-shot hardware block via the (do) handshake — you pick the convention per call site. Procedures are documented in full, with many examples, in their own chapter: Reusable Procedures.
