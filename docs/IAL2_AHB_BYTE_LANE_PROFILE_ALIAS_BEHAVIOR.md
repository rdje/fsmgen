# IAL2 AHB Byte-Lane Profile-Alias Behavior

Task-tree owner: `IAL2-FEATURE-COMPLETENESS-FRONTIER.739`

Date: 2026-06-30

## Outcome

`IAL2-FEATURE-COMPLETENESS-FRONTIER.739` ships the matching bounded public AHB
byte-lane/narrow-transfer subordinate `.ahb` profile alias:

```text
ppif/ahb_lite_subordinate_byte_lane.ahb
```

The alias mirrors the generic source:

```text
ppif/ahb_lite_subordinate_byte_lane.ppif
```

It keeps explicit `(profile ahb)`, the same
`(ahb-subordinate ahb_lite_subordinate_byte_lane ...)` object, and the same
byte/halfword/word narrow-transfer contract. The `.ahb` suffix remains an IAL2
profile alias over `protocol-platform-intent`; it is not a direct AHB-to-FSM or
AHB-to-HDL lowering path.

The generic `.ppif` fixture keeps its existing identity
`intent.ppif_ahb_lite_subordinate_byte_lane` with `source_kind` `ppif`.

## Lowering And Reports

The alias lowers through the same reviewable chain as the generic `.ppif`
source:

```text
.ahb / IAL2
  -> generated ahb_lite_subordinate_byte_lane.isf / IAL1
  -> generated ahb_lite_subordinate_byte_lane.fsm / IAL0
  -> HDL module ahb_lite_subordinate_byte_lane
```

The generated review artifacts match the generic `.ppif` source:

```text
ahb_lite_subordinate_byte_lane.isf
ahb_lite_subordinate_byte_lane.fsm
```

Check JSON and semantic JSON keep the authored `.ahb` source path. Schedule
JSON reports schema `fsmgen.ial2.protocol_intent.ahb_subordinate.v1`, target
profile `ahb`, target object `ahb-subordinate`, selected transfer
`ahb_lite_byte_lane_access`, generated `ahb_lite_subordinate_byte_lane.isf`,
generated `ahb_lite_subordinate_byte_lane.fsm`, and direct IAL2-to-IAL0
lowering disabled.

The alias report preserves `narrow_transfer_policy`, including accepted
`HSIZE` encodings, address rules, little-endian byte-lane masks,
inactive-lane-preserving writes, inactive-lane-zero-filled reads, and selected
ERROR policy. The alias removes `ahb_subordinate_profile_alias_deferred` from
its report because the alias itself is now shipped. The generic byte-lane
`.ppif` report keeps that historical residue.

## Preserved Boundaries

This slice does not change:

- the existing word-only `ppif/ahb_lite_subordinate.ppif` source;
- the existing word-only `ppif/ahb_lite_subordinate.ahb` alias;
- the generic byte-lane `ppif/ahb_lite_subordinate_byte_lane.ppif` support
  identity or report residue;
- generated byte-lane transfer behavior;
- aggregate/interconnect byte-lane propagation;
- optional/property-gated AHB signals;
- burst `SEQ` continuation;
- broader AHB interconnect/decode;
- direct backend behavior, verification-output generation,
  backend-language variants, AXI, APB, or VHDL behavior.
