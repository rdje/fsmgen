## Context

PGEN and ANVIL independently accepted the live-document containment
architecture with changes. Local inspection confirms real gaps in target versus
ceiling semantics, verifier execution proof, collection-index completeness,
route-candidate coverage, version-object retention assumptions, and packet
evidence presentation. It also finds one already-satisfied concern: the neutral
checker package is mechanically scanned for project and harness identity.

ANVIL's apparent 15,727-line IAL2 loss is a real accounting defect in the
packet, not demonstrated information loss. The complete former file remains an
exact Git object, the 844 authoritative task nodes remain in a content-addressed
segment, and the live root is a new overlapping view. Those products must not be
presented as a disjoint line partition.

PGEN proposes general date-based currency instruments; ANVIL supplies measured
false positives on legitimate closure and frozen-task dates. A portable policy
therefore cannot infer semantic staleness from date shape alone.

## Decision

1. Treat tracked-path coverage as classification only. Report migrated,
   pinned/deferred, generated, and pressure-slack evidence separately.
2. Replace ambiguous pressure semantics with explicit reviewed health targets
   and inclusive enforcement ceilings. Remove `hard_pct`; ratchet debt ceilings
   downward; require separate reviewed authority for any increase.
3. A declared verifier must be executed by the core/adapter or have a
   mechanically proved driver path. Presence-only checking cannot produce an
   unqualified green result; external execution is a visible degradation.
4. Currency is lifecycle-scoped and opt-in. A local verifier may check a
   declared currency contract, but the neutral doctrine does not impose a
   global newest-date or distinct-date heuristic and never equates size with
   semantic truth.
5. Migration evidence reports complete-source identity/retention, extracted
   semantic closure, live working-set reduction, and truly omitted-content
   residue as separate dimensions. Prefer content-addressed repository files
   for unrecoverable evidence; version objects require an explicit retention
   contract and actionable failure.
6. Every migration begins with `retain`, `merge`, `supersede`, `archive`,
   `delete`, or `re-form`. Deletion requires a fresh unique-content and
   classified-consumer proof with a negative control.
7. Route checks distinguish author-overflow destinations from reader navigation;
   collection indexes prove membership completeness; evidence maps prove their
   paths. Registry/record/value/line pressure and neutral-package identity are
   mechanical controls.
8. Decompose these corrections into separate leaves before wider reuse or
   affected family migration. Reviewer feedback itself changes no threshold,
   lifecycle, frozen content, landing content, or product behavior.

## Consequences

- The reusable doctrine reports what it actually proves and stops using one
  number for healthy state and transition quarantine.
- FSMGen avoids a false-positive global staleness gate while gaining explicit
  currency controls where a surface claims them.
- Existing IAL2 evidence is not discarded or relabeled as redundant; its Git
  retention assumption becomes an explicit remediation item.
- Utility can preserve a role while changing representation through `re-form`,
  and no migration mechanically preserves an obsolete file by default.
- The detailed response and exact leaf map live in
  `docs/LIVE_DOCUMENT_SIZE_CONTAINMENT_EXTERNAL_REVIEW_DISPOSITION.md`.
