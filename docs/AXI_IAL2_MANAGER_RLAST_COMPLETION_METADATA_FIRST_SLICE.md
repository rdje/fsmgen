# AXI IAL2 Manager RLAST Completion Metadata First Slice

Status: shipped for the public `.ppif` AXI manager capacity/status object.

Owner: `IAL2-FEATURE-COMPLETENESS-FRONTIER.51`.

Task tree:
[docs/tasks/IAL2-FEATURE-COMPLETENESS-FRONTIER.md](tasks/IAL2-FEATURE-COMPLETENESS-FRONTIER.md).

This slice implements the parser/report metadata boundary selected by
[docs/AXI_IAL2_MANAGER_RLAST_COMPLETION_CONTRACT_SELECTION.md](AXI_IAL2_MANAGER_RLAST_COMPLETION_CONTRACT_SELECTION.md).
It does not generate `RLAST` completion logic yet.

## Shipped Public Syntax

The existing `manager-capacity-status` `response-demux` read arm now accepts
the selected `burst-last` scope:

```text
(response-demux
  (read
    (response-event axi0_read_complete)
    (response-scope burst-last)
    (last-signal axi0_rlast (width 1))
    (transaction-completion generated)))
```

The shipped `single-beat` read response-demux syntax remains valid and
unchanged:

```text
(response-demux
  (read
    (response-event axi0_read_complete)
    (response-scope single-beat)
    (transaction-completion generated)))
```

`last-signal` is legal only with `response-scope burst-last`. It names the
AXI `RLAST` source and must declare width `1`.

## Static Validation

The parser and generator now fail closed on:

- `response-scope` values other than `single-beat` or `burst-last`;
- `response-scope single-beat` combined with any `last-signal`;
- `response-scope burst-last` without exactly one `last-signal`;
- malformed `last-signal` tuples;
- missing `last-signal` width metadata;
- `last-signal` widths other than `1`;
- generated or authored name collisions involving the `last-signal` name;
- pairing the current single-beat `read-data` contract with
  `response-scope burst-last`.

The existing read response-demux prerequisites still apply: the read arm
requires positive-width read ID-family metadata, read transactions, selected
read auto-ID lifecycle metadata, `response-event` equal to the top-level
`read-complete` event, and `transaction-completion generated`.

## Report Contract

Schedule/report JSON keeps the existing schema:

```text
fsmgen.ial2.protocol_intent.axi_manager_capacity_status.v1
```

For the checked-in sample, the report includes structural
`response_demux.read` metadata:

```text
response_demux:
  mode: bounded_response_demux_contract
  generated_behavior: false
  read:
    mode: bounded_read_rid_demux_contract
    generated_behavior: false
    response_event: axi0_read_complete
    response_event_role: raw_accepted_read_response_beat
    response_scope: burst_last
    response_id_signal: axi0_rid
    response_id_direction: generated_input
    last_signal: axi0_rlast
    last_signal_direction: generated_input
    last_signal_width: 1
    transaction_completion_source: generated_demux_last_beat
    transaction_completion_semantics: matched_rid_and_last_signal
    beat_valid_output: none
    burst_length_source: rlast_only
    burst_length_validation: not_generated
    generated_completion_signals:
      - axi0_r0_complete
      - axi0_r1_complete
    auto_transactions:
      - r0
      - r1
  residue:
    - generated_burst_last_read_demux
    - read_data_interleaving
    - bursts
```

`generated_behavior` is deliberately `false`: the report is a structural
contract, not a generated `RLAST` completion behavior claim.

## Generated Behavior

Generated `.isf`, `.fsm`, and SystemVerilog behavior remain unchanged from
the read auto-ID lifecycle capacity/status baseline used by this report-only
sample:

- `axi0_rlast` is not generated as an IAL1 input yet;
- `axi0_rid` is not generated by the burst-last report-only slice yet;
- transaction completion outputs/rules/assertions are not generated by this
  `burst-last` contract yet;
- read capacity release and read auto-ID release still use the authored
  completion events from the base capacity/status shell;
- the generated single-beat read response-demux sample remains the owner of
  shipped `RID` demux behavior.

This boundary prevents accidental implied burst behavior. Sources that also
request the current single-beat `read-data` contract are rejected when their
read response-demux arm uses `response-scope burst-last`.
